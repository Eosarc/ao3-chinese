# PR #69 回复建议（一）：分支管理与在线更新方式

> 适用场景：作为 PR #69 的评论回复，向贡献者解释为什么对于 AOT 在线术语表而言，直接在 `main` 分支更新比频繁新建 `patch-x` 分支更方便。

---

感谢为《Heated Rivalry》持续补充和更新术语表！❤️

在合并前，有一个关于 AO3 Translator（AOT）在线术语表的使用与更新小建议：

目前注意到你每次更新词条时，都会由 GitHub 自动生成一个新的分支（如 `patch-4`, `patch-5`）。在普通软件开发中这是常见操作，但对于 AOT 在线术语表来说，这种更新方式会导致调整、使用术语表时出现一些不便：

1. 自动更新机制失效：
   AOT 的在线术语表订阅是严格绑定 URL 的。如果读者导入的是 `.../patch-5/glossaries/Heated_Rivalry.txt`，当你下一次在 `patch-6` 更新时，由于读者的链接指向旧的 `patch-5`，插件就无法触发版本号比对与自动下载，读者必须手动重新获取并导入新链接。
2. 无法收录进 AOT 内置在线索引库：
   主仓库要把你的术语表收录进客户端设置面板的“在线术语库”一键导入列表中，链接必须指向固定的分支（推荐 `main` 主分支），而无法随着频繁变更的 `patch` 分支不断手动改动索引。
3. 避免旧版本内容覆盖：
   频繁新建分支如果分叉点没有同步主库最新提交，容易将之前修正好的格式或规范无意覆盖。

---

后续最推荐、最省心的更新方式（只需两步）：

① 同步主库更新
在你的 Fork 仓库首页（`https://github.com/CoffeHolic-330/ao3-chinese`）：
如果顶部提示落后主仓库，点击一下 「Sync fork」->「Update branch」，即可一键同步最新的所有文件和修复。
② 直接在 main 分支修改并提交
以后在网页端编辑 `Heated_Rivalry.txt` 后，在提交区域选择第一项：
* Commit directly to the `main` branch（直接提交到 main 分支）

提交前记得递增术语表元数据区的 `版本号`。

---

这样操作后：
* 所有订阅了你 `main` 分支链接的读者，只要你一保存，她们的 AOT 客户端就会自动检测并拉取更新，无需手动重新导入！
* 你的术语表也能顺畅被收录进 AOT 的官方在线术语中供所有用户浏览使用！
